# MK6 player, self-hosted (Docker / Podman)

A small web server that serves the MK6 slot player and the ROM zips from a folder you choose. It is a play-money simulator for preservation and study.

**ROMs are not included.** You must supply your own ROM zip files (for example `Queen Of The Nile.zip`) and own the right to use them.

## Run

Run these from the repository root (the `Dockerfile` and `docker-compose.yml` are there).

1. Open `docker-compose.yml` and change the first volume line to your ROM folder:

   ```yaml
   volumes:
     - /path/to/your/roms:/roms:ro             # <- your folder of .zip ROMs, mounted read-only
     - /path/to/your/roms/IMG:/roms/IMG        # <- the same folder plus /IMG: screenshots and banners are saved here
     - aristo-data:/data                       # writable: per-game notes
   ```

2. Start it:

   ```
   docker compose up -d --build
   ```

   (`podman compose` works the same way.)

3. Open <http://localhost:8791/> and pick a game.

Change the port with the `ports:` line (`"9000:8791"` serves on 9000). Use `"127.0.0.1:8791:8791"` to keep it off your network: there is no login.

## Adding ROMs

Copy zips into your ROM folder. The Games page lists them straight away (reload the page). Keep each ROM as the original zip. The folder is mounted read-only, so the container cannot change or delete your files. The ROM folder is the `ARISTO_ROMS` environment variable inside the container (`/roms`); the compose file sets it for you.

You can also drag a zip onto the Games page: that copy lives only in your browser, like the static variant.

## What is in the image

Only the server (`server.py`), the player pages (`web/`) and the small part of the tooling the Games page's "Scan screenshots" button uses. No ROMs, no documentation, no developer pages.

## Data

Images go to the `IMG` folder inside your ROM folder, one folder per game: `IMG/<game>/shot.png` (the screenshot from "Scan screenshots"), `IMG/<game>/marquee.png` or `marquee.jpg` (the banner, taken from the game's attract art by the scan or generated by the player the first time a game is played without one), and any image you upload for a game. The ROMs themselves stay read-only; only `IMG` is writable. Create it before the first start and let the container's user (id 10001) write to it, for example `mkdir /path/to/your/roms/IMG && sudo chown 10001 /path/to/your/roms/IMG` (with rootless Podman: `podman unshare chown 10001 /path/to/your/roms/IMG`). To keep images in `/data` instead, remove the `IMG` volume line and the `ARISTO_IMG` line from the compose file.

Per-game notes go to `/data` (the `aristo-data` volume). Delete the volume to reset them. To use a folder instead, replace `aristo-data:/data` with `./aristo-data:/data` and make that folder writable by user id 10001 (`chown 10001 aristo-data`). Set `ARISTO_READONLY: "1"` to make the page read-only.

## Notes

- Fedora, RHEL and other SELinux hosts: the container may see an empty ROM folder. Add `security_opt: ["label=disable"]` to the service, or end the volume with `:ro,z` (this relabels the folder).
- No login and no HTTPS: run it on a trusted network, or put a reverse proxy in front.
- Built with `docker compose` or `podman`; nothing is pushed anywhere.
